# 有邻 DAO：约 3 分 10 秒黑客松 Demo 设计方案

## 1. Demo 要讲清楚的唯一主线

> 三个有声誉的人用 R 为项目 A 背书；公众用 MON 支持并获得 P 与 R；捐款者凭 P 审核项目；完成一次可信协作后，原捐款者又用自己新获得的 R 共同发起项目 B。

这条主线体现的不是“一次募捐”，而是一个可以自我延续的公益协作循环：

```text
已有声誉者承担责任
  → 公众捐款并获得参与身份
  → 捐款者监督项目过程与结果
  → 贡献沉淀为新声誉
  → 原捐款者成为下一批项目发起人
```

Demo 的最后一幕必须回到第一幕的构图：开始时右侧是“没有 R 的捐款者”，结束时右侧三人已经出现在项目 B 的共同发起人列表中。这是全片最重要的闭环。

### 1.1 片头名称动画：“德不孤，必有邻”

Demo 最前面增加约 10 秒的全屏名称动画，沿用现有网站的米白底色、深绿色文字和 Logo 视觉：

| 时间 | 动画 |
| --- | --- |
| 00:00–00:03 | 画面中央逐字出现“德不孤 必有邻”，暂不显示 DAO； |
| 00:03–00:05 | 完整句子停留，让观众读清名称出处； |
| 00:05–00:07 | “德不孤 必”四字淡出，只留下“有邻”； |
| 00:07–00:09 | “有邻”平滑向左移动到正式品牌字标的位置； |
| 00:09–00:10 | 右侧补出“DAO”，下方 Logo/英文标识轻微显现，最终形成现有“有邻 DAO”品牌锁定画面。 |

文字删除和移动应使用平滑遮罩与缓动，不使用爆炸、粒子或过度 Web3 化的特效。动画结束后直接淡入四个公益问题卡片。

### 1.2 叙事结构改为“开头四问—中间验证—结尾四答”

开头不先介绍产品，而是用 2×2 卡片在 18 秒内提出四个公益协作问题：

1. **资金一次打完，后续如何问责？**
2. **规则由平台维护，谁能保证不被单方面修改？**
3. **参与结束以后，个人留下了什么可信履历？**
4. **发起、质疑和公共决策如果不用承担成本，会发生什么？**

卡片文字必须短，详细解释由旁白完成。中段通过 A→B 的真实交易逐一给出证据。结尾让同样四张问题卡原位翻转成四个回答：

1. **两轮募捐 + 中期评分闸门**：先验证，再开放第二轮；
2. **不可单方篡改的合约状态机**：资金、时间、资格、评分和结算均由合约执行；
3. **P + R 双层履历**：P 记录项目参与关系，R 沉淀可复用的全局声誉；
4. **双向质押与挑战机制**：发起人、挑战者和争议投票者都要用 R 承担责任。

这样不会把四点做成前后各讲一遍的 PPT，而是形成“问题—现场验证—答案”的叙事闭环。

## 2. 推荐形式：真实交易 + 双视角剪辑，不做全程连续直播

### 2.1 画面布局

采用 16:9、1920×1080 画面：

- 左侧约 44%：项目发起人界面；
- 右侧约 44%：捐款者/评分者界面；
- 中间约 12%：链上状态轨道和当前生效的合约；
- 底部：一句话字幕、交易状态和必要的 Monadscan 链接提示。

中间状态轨道固定显示：

```text
共同发起 → 第一轮 → 中期审核 → 第二轮 → 结项 → 新项目 B
```

当前阶段高亮，已经完成的阶段打勾。每次发生链上交易时，画面中央短暂出现：

```text
Wallet signed → Monad Testnet confirmed → UI restored from chain
```

### 2.2 视觉语义

- MON：金色 `#C9A227`，表示资金；
- P：紫色 `#6F5BD3`，表示不可转让的项目参与凭证；
- R：深绿色，沿用现有网站的统一声誉视觉；
- YoulinProtocol：深色主卡，表示规则与状态机；
- YoulinParticipation：紫色小卡，表示 P 的铸造与资格验证；
- YoulinReputation：深绿色小卡，表示 R 的铸造、锁定、解锁和奖惩。

Demo 不另建一套颜色体系：P、R、MON、按钮和合约卡片均直接沿用现有网站的色彩与组件。R 的余额、质押、解锁、销毁和奖励通过箭头、锁图标及正负号表达，不通过改色表达。

不在主流程中展示 `YoulinGenesisTreasury` 和 `YoulinProfileRegistry`，避免短片中出现与核心闭环无关的分支。

### 2.3 为什么必须剪辑时间

当前 Monad Testnet 演示参数为：

| 时间规则 | 当前值 |
| --- | ---: |
| 最短预计项目周期 | 60 秒 |
| 中期评分窗口 | 120 秒 |
| 结项评分窗口 | 120 秒 |
| 挑战窗口 | 180 秒 |

因此应预先用真实交易跑完项目 A 和项目 B 的创建，再录制或回放关键交易。时间跳转必须在画面中明确写成“链上时间推进 120 秒”，不能让观众误以为合约没有时间约束。

建议只完整展示两次钱包确认：第一次共同发起质押、第一次捐款。其余同类账户操作用 3–5 倍速和“3/3 已确认”聚合动画呈现。

## 3. 专用演示数据设计

为了证明“捐款者靠项目 A 获得 R，随后发起 B”，建议新建一组专用于视频的真实测试网项目，不直接复用已被 bootstrap 初始化过 100 R 的旧捐款账户。

### 3.1 账户分组

| 分组 | 数量 | 初始条件 | Demo 中的角色 |
| --- | ---: | --- | --- |
| A 发起人 | 3 | 已有可用 R | 发起 A、分别质押 R、提交材料 |
| A 捐款者 | 3 | 初始 R = 0，有少量测试 MON | 首轮捐款、中期评分、二轮捐款、结项评分 |
| 权限外推进账户 | 1 | 有少量测试 MON | 在时间窗口结束后调用公开的定分和结算函数 |

所有地址可以公开，私钥只能保存在本机被 Git 忽略的 `.env` 中，绝不进入网页、视频、终端截图或仓库。

### 3.2 建议金额

项目 A：**乡村校园安全饮水计划**。

- 总目标：`30 MON`；
- 三位发起人：各质押 `10 R`，合计 `30 R`；如初始 R 不足，先各向创世项目捐 `10 MON` 获得 `10 R`；
- 第一轮目标：`15 MON`，三位捐款者各捐 `5 MON`；
- 中期评分：三人都评 8 分，最终显示 80 分；
- 第二轮最多可继续募集 `15 MON`；本次 Demo 中三位捐款者各捐 `5 MON`，展示项目继续获得充分支持并达到总目标；
- 结项评分：三人都评 9 分，最终显示 90 分；
- 挑战窗口结束后：无挑战结算。

结项 90 分对应的发起人 R 变化必须进入正片。当前合约按 `质押额 × 结项分 / 80` 计算结算量，因此每位发起人的变化为：

```text
10.00 R 锁定
→ 10.00 R 全部解锁
+ 1.25 R 高分奖励
= 11.25 R 项目结算价值
```

三位发起人合计获得 `3.75 R` 高分奖励。画面同时给出对照刻度：`<60 全部销毁｜60–79 部分销毁｜80 原额返还｜>80 返还并奖励`。

每位捐款者从项目 A 获得：

| 来源 | 获得的 R |
| --- | ---: |
| 首轮捐款达标后主动领取 | 5.00 R |
| 完成中期评分 | 0.10 R |
| 第二轮捐款即时获得 | 5.00 R |
| 完成结项评分 | 0.10 R |
| 合计 | 10.20 R |

项目 B：**偏远地区青少年编程启蒙工作**。

- 总目标为 `30 MON`；
- 项目 A 的三位捐款者成为 B 的三位共同发起人；
- 每人用 A 中获得的 R 质押 `10 R`；
- 合计质押 `30 R` 后激活项目 B；
- Demo 到项目 B 进入第一轮募捐即结束，不需要再跑 B 的完整生命周期。

由于三位捐款者初始 R 为 0，结尾展示其 R 余额变化和 B 的质押记录，就能形成最清晰的链上因果证据。

## 4. 四道质量门槛如何进入 Demo

结论：**四道门槛都应在正片留下视觉记忆，但正片只讲清规则和本次项目的通过结果，公式、失败分支和制度讨论留给问答。**

视频中固定出现四道“Gate”印章：

| 门槛 | 正片中的展示 | 问答中补充 |
| --- | --- | --- |
| Gate 1：共同发起与 R 背书 | 三位账户分别签名、各锁定 10 R；合计达到目标后项目激活 | 发起人数随目标额变化、质押为何形成责任成本 |
| Gate 2：首轮达到 50% | 首轮进度从 0 跳到 50%，状态才进入中期材料提交 | 未达 50% 时项目失败、捐款者可退款 |
| Gate 3：中期检验与继续支持 | 中期 80≥60 后二轮才开放；二轮捐款把总额补至 100% | 对数权重如何降低大额账户垄断 |
| Gate 4：结项奖惩与挑战 | 结项 90 分后展示发起人 R 解锁和 +12.5%；用 4 秒分支图提示低分销毁、挑战输赢均有成本 | 60/80 分界、挑战与争议投票的完整路径 |

### 4.1 Gate 3 是“开放资格 + 继续表态”，不是二轮募满要求

当前部署合约的硬门槛是：**中期评分达到 60 分，才允许进入第二轮募捐**。第二轮采用弹性筹款：筹集到多少，就用多少资金继续完成项目，不要求二轮募满才可以结项。

本 Demo 让项目 A 在二轮继续获得 `15 MON`，最终达到 `30 MON` 总目标，以便清楚展示中期结果如何影响后续捐款决定。旁白使用“通过中期检验后，公众再次用资金表态”，不把募满描述成强制条件。

## 6. 每一步实际对应的合约行为

| Demo 步骤 | YoulinProtocol | YoulinReputation | YoulinParticipation |
| --- | --- | --- | --- |
| 1. 共同发起 A | `createProjectDraft`、`acceptInitiation`、`activateProject`；检查人数及合计质押 | `lockByProtocol` 锁定发起人的 R | 不参与 |
| 2. 第一轮捐款 | `donateRound1`；首轮达到总目标 50% 后切换状态 | `claimRound1DonationReputation` 后按首轮捐款额铸造 R | 首次有效捐款时铸造项目 A 的 P |
| 3. 中期材料与评分 | `submitMidReview`、`submitMidScore`、`finalizeMidScore`；按 `ln(1 + donationMON)` 加权 | 每次有效中期评分奖励 `0.1 R` | 验证评分者确实持有 A 的 P |
| 4. 第二轮募捐 | 仅 `midScore ≥ 60` 时允许 `donateRound2`；MON 直达项目钱包 | 非发起人的二轮捐款即时铸造等额 R | 新捐款者首次参与时获得 A 的 P |
| 5. 结项与评分 | `submitFinalReview`、`submitFinalScore`、`finalizeFinalScore`、`settleWithoutChallenge` | 评分奖励 R；结项分决定发起质押的返还、销毁或高分增发 | P 永久保留，继续证明该地址参与过 A |
| 6. 发起 B | 原 A 捐款者调用 B 的 `acceptInitiation`，达到人数和质押门槛后激活 | 把在 A 中获得的统一 R 锁定到 B | A 的 P 继续显示在三人的历史履历中 |

三合约在画面中的一句话解释：

- `YoulinProtocol`：管资金、时间、评分资格和状态转换；
- `YoulinParticipation`：记录“谁真正参与过哪个项目”的不可转让 P；
- `YoulinReputation`：把贡献变成不可转让 R，并在发起项目时锁定责任。

## 7. 建议旁白全文

> 有邻，取自“德不孤，必有邻”。公益不会孤立发生，它因善意而传播，也因共同参与而延续。
>
> 公益项目常遇到四个问题：资金一次打完以后难以问责、无法有效追踪项目进度；规则由平台单方维护；个人参与留不下可信履历；发起和质疑又常常不需要承担责任成本。
>
> 有邻 DAO 致力于解决这些问题。接下来，我们用一个完整的参与流程展示解决方案。
>
> 有邻 DAO 是一个以账户为中心的公益 DAO。账户有两类不可转让的链上记录：P 是项目参与凭证，记录一个账户真正参与过哪些项目，并决定其审核资格；R 是统一声誉，汇总账户跨项目的贡献，可以继续用于发起、质押和公共决策。YoulinParticipation 负责 P，YoulinReputation 负责 R，YoulinProtocol 则执行资金、时间、评分和状态转换。
>
> 首先，项目方上传“乡村校园安全饮水计划”。一个项目不能由单个账户单独发起：它需要获得多位声誉持有者的共同认可，发起人分别确认并锁定自己的 R。只有共同发起人数和总质押都达到合约门槛，项目才进入第一轮募捐。
>
> 第一轮中，一批此前没有 R 的账户参与捐款。首次有效捐款会为捐款者铸造该项目的 P；首轮达到合约设定的阶段目标后，他们还可以领取与首轮捐款等额的 R。项目方取得第一阶段资金，并在时限前提交采购、到货和安装进度等中期材料。
>
> 只有真正向项目捐过款、持有项目 P 的账户才能对项目进行中期评分。评分按捐款额对数加权，既承认投入差异，也避免大额账户完全垄断。只有中期评分通过合约设定的及格线60分，第二轮募捐才会开放。
>
> 第二轮筹集多少，项目就用多少继续推进。潜在捐款者可以参考中期结果，决定是否继续投入。项目完成后，项目方提交安装成果、水质检测和签收记录，所有捐款者再根据最终履约情况完成结项评分。
>
> 结算时，合约根据结项评分处理发起人的质押：项目执行情况不佳会损失 R，达到基准会返还质押，而如果执行优秀还会获得额外声誉。结项后还会开放挑战窗口：挑战者也必须质押 R，挑战失败会损失 R；发生争议时，公共投票同样需要锁定声誉。发起、质疑和裁决都不是免费按钮。
>
> 最后，“乡村校园安全饮水计划”项目的捐款者已经通过捐款和评价积累了 R。他们从参与者变成共同发起人，用这份新获得的声誉共同发起“偏远地区青少年编程启蒙工作”。两轮募捐解决资金问责，合约状态机保证规则不可单方篡改，P 与 R 留下可信公益履历，双向质押建立责任成本。在有邻 DAO，一次公益参与，正是下一次公共行动的起点。


### 7.1 旁白录制节奏

- 前 10 秒配合名称动画说明“有邻”的出处与内涵；随后 18 秒提出问题，语速稳，不展示操作；
- P 与 R 的定义需要清楚停顿，字幕分别保留至少 4 秒；
- 同类的三笔签名、三笔捐款和三次评分使用倍速画面，旁白按机制而不是逐笔念账户；
- `15/30 MON`、`80/100`、`90/100`、`10 R → 11.25 R` 和 `0 → 10.2 R` 五组数字需要在画面中停留；
- 结尾四个答案逐项亮起，但旁白连续说完，最后一句后预留约 1 秒显示 Logo 与网址。

## 10. 失败保护与备用素材

- 所有关键步骤先保留交易哈希、网页截图和 Monadscan 页面；
- 正式录制前跑一遍只读检查脚本，确认项目状态、R、P 和账户余额；
